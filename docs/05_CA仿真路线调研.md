## 三、实证结果(hello_cann 直跑)

接入配方(LD_LIBRARY_PATH):
```
/tmp/ca_lib/libruntime.so → 符号链接到 libruntime_camodel.so   # 顶替 DT_NEEDED libruntime.so
/tmp/ca_lib/ 内含仿真器全部 so 的链接 + libascend_hal.so(vdriver 产物,仅兜底
  满足 libopapi/libnnopbase 的 DT_NEEDED——camodel runtime 自己不用它)
LD_LIBRARY_PATH=/tmp/ca_lib:$TK/lib64:simulator/Ascend910B1/lib:$TK/../lib64
```
- ✅ **ACL init successfully**(libruntime_camodel 全链加载成功)
- ❌ rtSetDevice 507033:`halSqCqAllocate` 返回 3(CA 驱动内部拒绝),StarsEngine
  构造 3 秒后析构;CAMODEL_LOG_PATH 无日志产出(闭源,内部原因待查)

## 四、与 vdriver 的定位对比

| | vdriver(假 HAL) | CA/CAMODEL(官方仿真) |
|---|---|---|
| 内核执行 | 不执行(数值非目标) | **x86 真仿真执行,数值正确** |
| 形状数据依赖算子(nonzero/topk 路由/掩码) | 全部踩坑,需 host 回退 shim | 应原生支持 |
| 维护方 | 自研(语义缺口自担) | 官方(cmodel_driver + 仿真模型随包) |
| 速度 | ~原生 | 慢 2-4 个数量级(整芯片 CPU 模拟),仅适合算子/小网络级 |
| 大模型训练(Kimi-K3) | 流程可推(待收口) | 不现实 |
