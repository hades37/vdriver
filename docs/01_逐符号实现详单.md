## 二、VIRTUAL vs PHYSICAL 建议

**建议报 `RUN_MACHINE_VIRTUAL`(1)+ `INFO_TYPE_ADDR_MODE=非0(flat)`**。依据:
- `RUNTIME_WHEN_NO_VIRTUAL_MODEL_RETURN`(npb:271):仅当 `sysMode_==VIRTUAL && addrMode_!=0` 才短路——命中后跳过 HostAddrRegister/HostAddrUnRegister(npu_driver_mem.cc:288/302),少实现 halHostRegister/halHostUnregisterEx 两个弱符号。
- npu_driver_res.cc:1561-1565:VIRTUAL+flat 时 cqeDepth 强制 256(CQ_DEPTH_FOR_FLAT_ADDR_VIRTURE_MACH,npb:240),mock 资源面更小。
- addrMode_ 非 0 同时置 g_isAddrFlatDevice(raw_device.cc:554-560),带来 halSqCqAllocate 失败自动重试(npu_driver_res.cc:1577),mock 恒 0 不受影响。
- 报 PHYSICAL(0/0)则会走 halHostRegister 真实注册路径且 cqeDepth=1024,mock 表面积更大。RUNTIME_WHEN_NO_VIRTUAL_MODEL_RETURN 影响的函数即上述两个 Host 注册函数,无其他。

## 三、SoC 信息来源

SoC 型号**不经 hal**:`chipType_/properties_/featureSet_` 来自 runtime 编译期注册表 DevInfoManage(npu_driver.cc:37-41;`GET_DEV_PROPERTIES`=dev_info_manage.h:128,由各芯片 `REGISTER_DEV_PROPERTIES` 注册)。hal 侧仅两处旁路:halGetChipInfo 仅用于 310P 细分(runtime.cc:580-595 读 chipInfo.name 匹配 310P5/P7);halGetChipFromDevice 仅多芯片特性。**填错后果**:halGetDeviceInfo INFO_TYPE_VERSION 错→hardwareVersion 判定错、部分平台分支错;halGetChipInfo.name 错→仅 310P 细分型号字符串错;halGetChipFromDevice 错→多芯片 chipId 映射错(默认关闭不触发)。属性表(sqDepth/cqeSize 等)填错 hal 侧无法纠正。

## 四、CQE 最小字段

- 逻辑 CQE `rtLogicReport_t`(task.hpp:148-162):**phase(必须翻转,作 CQE 有效性位)、SOP=EOP=1、streamId、taskId、logicCqType=LOGIC_RPT_SUCCESS(0)、errorCode=0**;logicCqId/payLoad 按需。
- TS 旧格式 `rtTaskReport_t`(task.hpp:27-42):SOP/EOP、streamID:10、taskID、phase、SQ_id、SQ_head。
- 回调 CQE `rtHostFuncCqReport_t`(task.hpp:92-108):**hostFuncCbPtr 必须非 0**(api_impl_david.cc:1394 空则 RT_ERROR_DRV_REPORT)、streamId/taskId/eventId/isBlock、phase 翻转。
- **可全部回避**:vdriver 让 halCqReportGet 恒 count=0,任务完成走 halSqCqQuery(SQ_HEAD 前进)+FinishedTaskReclaim(stars_engine.cc:395/709)回收,无需产 CQE——这是最小可行路径。
